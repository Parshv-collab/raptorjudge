# Full-stack audit — backend ⇄ frontend parity

> **Historical snapshot (issues 1–31).** Its counts are "at audit time" and have
> since moved; it is kept because it records *why* each export was deleted, wired
> or kept. For the current, re-measured ledger see
> [FINAL-REVIEW.md](FINAL-REVIEW.md) (verified 2026-09-29), and for the current
> state of the app [README.md](README.md).

Scope: every export in `src/convex/`, every HTTP route in `src/convex/http.ts`, every
`useQuery`/`useMutation` in `src/pages|components`, every page file vs every route in `src/App.tsx`.
Generated by static cross-referencing (export name → call-site search) plus manual review of each hit.

Totals at audit time: **172 backend exports** (queries / mutations / actions / internal variants),
**2 HTTP routes** (`/api/v1/*` — everything else is served by Convex's own HTTP surface),
**0 `fetch("/api/…")` calls in the client** (the SDK talks to Convex directly; REST is the
machine-facing surface used by the acceptance harness and scripts).

## 1. Orphans — backend exports with no caller

### 1a. Genuine orphans found and **resolved by deletion** (dead surface)

| Export | Why it was dead | Resolution |
| --- | --- | --- |
| `events.get` | Every caller resolves events by slug (`events.getBySlug`) or via a public variant. Duplicated `assertEventVisible` gating. | **Deleted** |
| `judging.leaderboard` | Added for the results ordering work, but `submissions.publicGallery` already returns the *same* order from the *same* `rankEventProjects` helper (gallery = `rank` + `isWinner` per card), and the organizer Results tab renders `normalization.analyze` + `pairwise.leaderboard`. | **Deleted** (no behaviour change: one source of truth in `lib/results.ts`) |
| `teams.getTeam` | Roster/visibility gating is served by `teams.myTeams` (self) and `teams.listByEvent` (staff). No page, route or test referenced it. | **Deleted** |
| `tracks.remove` (hardening) | Existed but was unguarded: deleting a track in use silently orphaned teams/submissions. | **Kept, now fails closed** while teams/submissions still reference the track |
| `comments.canModerate` | A per-comment permission read with no callers — the project page already derives moderation rights from `users.me`, and `deleteComment` re-checks server-side. | **Deleted** |
| `judging.allScores` | Superseded by `normalization.analyze` / the export queries; no caller. | **Deleted** |

### 1b. Orphans that were **real missing wirings** — now wired

| Export | Gap it exposed | Resolution |
| --- | --- | --- |
| `judging.verifyJudgeRecord` | `/verify/judge/:uuid` rendered a green “Judge record verified” banner from **query-string values only** — it never called the backend, so any URL with a signature looked valid. | `Verify.tsx` now verifies against the backend (constant-time HMAC check) and shows failure states |
| `judging.judgeRecord` | Only surfaced as a URL from the judge console; the record itself was never renderable. | Same page renders the real record (issued-at, counts) once verified |
| `comments.unflag` | “Flagged Comments” tab could delete a comment but not clear a false report. | “Unflag (keep)” action added next to Delete |
| `voting.castVote` / `voting.removeVote` | Community voting existed end-to-end on the server (window gating, quadratic/upvote mode, credits) but no participant surface ever called it — votes could only come from the seeder. | “Community vote” panel on the project page (points for quadratic, single upvote for upvote events, remove own vote) |
| `events.enrolled` | Participant dashboard filtered `events.listPublic` against `teams.myTeams` client-side (N+1 reads, and any event the user left/joined drifted). | Dashboard now reads the server-side `events.enrolled` |
| `events.listMine` | Organizer console used `events.listAll` (every event on the platform) with **no** scoping. | `OrganizerDashboard` + `OrganizerEvents` now use `listMine`; seed now sets `organizerId` so the fixture event has a real owner |
| `exports.assignmentsCsv` | Judge-assignment export had no UI (only submissions/rankings/scores CSVs had buttons). | Export button added to the organizer Results tab |
| `exports.eventJson` | Same — the full event dump was unreachable from the UI. | Export button added |
| `certificates.listByEvent` | Certificates could be issued by the seeder but the organizer had no view of what was issued. | “Issued certificates” card in the Results tab (recipient, UUID, verify link) |
| `webhooks.setActive` | A webhook could be registered and tested but never paused. | Active/Inactive toggle on each endpoint row |
| `webhooks.dispatch` | **Dead feature**: nothing ever fired an event, so registered endpoints only ever received `testDelivery`. | Scheduled from `submissions.submit`, `judging.submitScores` and `events.publish` |
| `mfa.adminReset` | Admins could reset passwords but not a lost 2FA device (lockout = permanent). | “Reset 2FA” action in `/admin/users` |
| `admin.updateLookup` | Lookup tables were create-only — a typo’d label could never be fixed. | Edit (label / active / order) in `/admin/settings` |
| `tracks.update` | Tracks were create-only; a misspelled track name was permanent once submissions referenced it. | Inline “Rename” on each track card |
| `acceptance.saveReport` / `acceptance.latestReport` | `acceptance.ts` documented a report “visible on dashboard + `/api/v1/acceptance`”, but nothing ever stored or displayed one — only the REST response carried it. | “Acceptance self-check” card on the admin dashboard: run, store, render |

## 2. Frontend → backend

- **0 dead buttons.** A JSX scan for `<Button>` without `onClick` / `type="submit"` / `href` returned
  37 hits; all 37 are wrapped in `<Link>` or `<a>` (whose navigation *is* the action), or are the
  disabled state of a real handler. No handlers were missing.
- **0 `fetch("/api/…")` calls.** No client code depends on a REST endpoint that may not exist.
- Every `useMutation`/`useQuery` resolves to an exported backend function — no `undefined` handles.
- Several call-sites used `(api.x as any).y` casts to dodge stale codegen types. Audited each one;
  they all resolve to real exports, and the casts are the only reason a grep-based audit can
  produce false orphans.

## 3. Routes ⇄ pages

- Every `<Route path>` in `src/App.tsx` has a page component; every page under `src/pages/` is
  imported by `App.tsx` or by another page (`organizer/JudgesTab`, `organizer/RubricTab`,
  `organizer/WinnerOverridePanel` are tab components used by `OrganizerEventManage`).
- **0 page-without-route**, **0 route-without-page**, **0 nav entry without a route**.
- Role groups are wrapped in `ProtectedRoute` with the required role; `/profile`, `/settings`,
  `/security`, `/search` accept any signed-in role; `/` renders the marketing page only when
  signed out (`LandingGate`).
- Route paths were **not** changed (locked by the acceptance harness).

## 4. Data-shape mismatches

- **0 snake_case reads** on the client (`repo_url`, `team_id`, …) — the API is camelCase end-to-end
  and the client never reaches into raw rows.
- `submissions.detail` and `submissions.publicGallery` both expose `rank`, `isWinner` and
  `resultsPublished`, so `Gallery.tsx` and `ProjectDetail.tsx` render the same result state.
- `events.enrolled` returns `participantCount`; the dashboard reads exactly that key.
- `verifyJudgeRecord` returns `{ valid, reason? , judgeName, eventName, projectsScored, totalScores }`
  and `Verify.tsx` now consumes that shape instead of the URL query string.

## 5. States / hygiene

- Empty, loading and error states audited page by page: pages that can receive an empty collection
  render `EmptyState`; loading paths render skeletons; all `catch` blocks route through
  `humanizeConvexError` (and auth through `describeSignInFailureForUser`) — no raw error reaches a user.
- `TODO` / `FIXME` scan: **0** in source. The only “coming soon” string is the legitimate event-status
  label `Coming Soon` in `src/lib/eventStatus.ts`.
- Hardcoded colours: all values outside `src/styles/design-tokens.css` are legacy hex inside
  `tailwind.config.js` token definitions; component code uses token utilities only.
- Privileged mutations audited for audit-trail writes; `mfa.adminReset` already wrote the chain, and
  `admin.updateLookup` + `webhooks.setActive` now do too, as do the new webhook dispatch call-sites.

## 6. Acceptance surface (T1/T2) — untouched

`run.py`, `fixtures.json`, `spec.md`, `.dogfood.toml`, `docker-compose.yml`, `nginx.conf` were not
modified. Route paths, HTTP route behaviour, export CORS policy and the seeded slug/status are
unchanged. The gallery ordering rule (seeded shuffle before publication, ranked after) already
lived in `submissions.publicGallery` and was not altered; the 7/7 checks exercise those HTTP paths.
